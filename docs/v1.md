# RulerCraft v1: what "finished" means and how we get there

Status: *Definition (2026-11-07, D-012; delivered inside SolidCraft since 2026-11-18, D-014 and D-015)*. Serves
INTENT.md. Detailed capability list: docs/specs/product-scope.md.

## Who decides it is finished

**The SolidCraft community.** v1 is done when a person who already designs in SolidCraft and prints or scans
parts can do the four jobs below on their own parts, **inside SolidCraft** with the RulerCraft plugin installed,
without reading code or docs first, and says they would use it. Until such people try it, Logan stands in for
them. Outreach to that community is Logan's (we contact no one).

## The four jobs

| Job | v1 bar, in SolidCraft |
| --- | --- |
| **Scan to editable CAD** | open a scan (STL, PLY, OBJ, 3MF, glTF/GLB) and get an editable part whose sizes are named parameters: plates with any outline, holes (through, blind, counterbored), bosses, steps and pockets, slots; what is not rebuilt is listed in the import report; the rebuilt part checked against the scan |
| **Inspect a part** | measure a scan inside SolidCraft: fit planes, cylinders and spheres to picked regions, distances and angles, flatness and form, deviation from the design, wall thickness, with each number's method stated |
| **Work with an agent** | everything above reachable by Claude through SolidCraft's MCP server, where installed plugins appear as tools, and through RulerCraft's own MCP server and CLI |
| **Be an engine for others** | the engine is a documented Rust library (git, then crates.io) that builds for WebAssembly, so any host can use it |

And underneath all four: numbers that match known answers (D-003), local only, MIT OR Apache-2.0.

## How it reaches people

The SolidCraft plugin package (`plugin/solidcraft`, docs/specs/solidcraft-plugin.md), published as a `.zip` on
RulerCraft's GitHub releases; install with SolidCraft's **Preferences › Plugins › Install plugin…**
(docs/install-solidcraft-plugin.md). SolidCraft provides the window, 3D view, selection, undo and files.
RulerCraft's CLI and MCP server stay for scripts, CI and agents; the browser viewer (`rulercraft-gui`) is a
developer tool.

## Phases

Each phase ends with a plugin release Logan installs and a short "what changed, what to try" note.

| Phase | Delivers | Ends when |
| --- | --- | --- |
| **S0 Importer** (done) | scan opens as a plate with holes, named sizes, import report, SolidCraft's own volume check; release and install guide | Logan installs it in his SolidCraft and opens a scan |
| **S1 Real parts** | a printed and scanned plate measured with calipers; fixes from what it shows | the rebuilt part's sizes match the calipers within the scan's accuracy (R1 exit) |
| **S2 More shapes** | any outline, bosses and pins, steps and pockets, counterbores, slots; a deviation check of the rebuilt part against the scan in the report | a downloaded prismatic part rebuilt within 0.05 mm of its mesh (R2 exit) |
| **S3 Inspect in SolidCraft** | command entries that fit and measure picked regions of a scan, within SolidCraft's mesh-size limit or around it | a dimensioned check of a known part done entirely in SolidCraft, numbers equal the CLI's |
| **S4 Release candidate** | documentation, engine on crates.io, polish from users | Logan, and then SolidCraft users he hands it to, finish all four jobs without help |

## What only Logan provides

Real parts and scans with caliper or published numbers (S1, R1's exit); trying each release in his SolidCraft;
a yes at each publishing moment (crates.io, announcing releases); raising with SolidCraft's maintainers any plugin
limit that blocks a job. Everything else follows defaults recorded in DECISIONS.md, and open questions go in
HANDOFF.md with the default picked.
