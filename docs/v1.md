# RulerCraft v1: what "finished" means and how we get there

Status: *Definition (2026-11-07, D-012)*. Serves INTENT.md. Detailed capability list: docs/specs/product-scope.md.

## Who decides it is finished

**The SolidCraft community.** v1 is done when a person who already designs in SolidCraft and prints or scans
parts can do all four jobs below on their own parts, in a native app that looks and feels like part of the
SolidCraft family, without reading code or docs first, and says they would use it. Until such people try it,
Logan stands in for them. Outreach to that community is Logan's (we contact no one).

## The four jobs (all of them, each to a minimum bar)

| Job | v1 bar |
| --- | --- |
| **Inspect a part** | open multi-million-triangle STL/PLY/OBJ/3MF smoothly; fit plane, sphere, cylinder, cone and circle by click-to-grow, brush or lasso; build points, lines and planes; dimensions with nominal ± tolerance and pass/fail; flatness, parallelism, perpendicularity, coaxiality; deviation map against a design mesh; wall thickness map; sections; a report; save, reopen, undo |
| **Scan to editable CAD** | find the part's faces and holes automatically; show the build recipe with its evidence; send it to SolidCraft so an editable part appears there; check the rebuilt part against the mesh; STEP through SolidCraft |
| **Work with an agent** | everything above is reachable by Claude (MCP) on the same open document the person is looking at; what the agent does shows up in the app and can be undone |
| **Be an engine for others** | the engine is a documented Rust library (git, then crates.io), one JSON command entry point that mirrors the MCP tools, and a Wasm build, so SolidCraft or anyone can use it however their plugins end up working |

And underneath all four: numbers that match known answers (D-003), local only, MIT OR Apache-2.0.

## The app

A native desktop app on egui and wgpu, the same toolkit and versions SolidCraft uses (D-012):

- `rulercraft-ui`: the panels and the 3D viewport (wgpu: indexed drawing, GPU picking, overlays), with no window of
  its own, so a host such as SolidCraft could show them if it ever takes native or Wasm panels.
- `rulercraft-app`: the window, menus, files and settings around them (eframe); Linux, Windows and macOS.
- Look: SolidCraft's theme (same toolkit, MIT OR Apache-2.0), adopted with a NOTICE.
- Later: the same code compiled for the browser (egui supports it; SolidCraft ships a web build this way).
- The browser viewer built earlier (`rulercraft-gui`, D-009) stays as a light prototype and test harness; new app
  work goes into the native app.

## Phases

Each phase ends with a build Logan runs and a short "what changed, what to try" note. Phases overlap where they do not
depend on each other; pacing follows the credits available.

| Phase | Delivers | Ends when |
| --- | --- | --- |
| **P0 Native foundation** | native app with SolidCraft look: open, view (wgpu), mark, fit, measure, find regions; the shared spatial index; the JSON command entry point | the native app does everything the browser prototype does, with the same numbers |
| **P1 Inspect core** | constructions, dimensions, tolerances and pass/fail; GD&T checks; projects and undo; report; big meshes (threads, level of detail, GPU picking) | a dimensioned report of a known part, saved and reopened, numbers equal the CLI's; a 5-million-triangle scan stays smooth |
| **P2 Compare** | deviation map, alignment (auto, three-plane datum, symmetry), thickness map | a deliberately bumped copy of a known part shows the bump at the right size, after auto-alignment |
| **P3 Scan to CAD** | recipe panel, send to SolidCraft, rebuilt-part check, STEP, cone and torus fits | a prismatic downloaded part rebuilt in SolidCraft within 0.05 mm (R2 exit) |
| **P4 Agent in the app** | the app shares its open document with Claude over MCP (opt-in, local); agent actions visible and undoable | Claude measures a part while Logan watches it happen in the app and undoes one step |
| **P5 Release candidate** | sections, mesh clean-up, polish, installers for three platforms, engine on crates.io, Wasm build | Logan, and then SolidCraft users he hands it to, finish all four jobs without help |

## What only Logan provides

Real parts and scans with caliper or published numbers (R1's exit); SolidCraft running when P3 starts; a yes at
each publishing moment (installers, crates.io); feedback on each phase build. Everything else follows defaults
recorded in DECISIONS.md, and open questions go in HANDOFF.md with the default picked.
